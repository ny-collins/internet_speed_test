# Layout Redesign Plan: Google Fiber Style

**Objective:** Transform the current "cramped" layout into a spacious, stage-based design inspired by the Google Fiber Speed Test.
**Goal:** Integrate the graph dynamically with the active test phase rather than having it as a separate, floating "variance" box.

---

## 1. The "Stage & Tray" Concept

The core difference between your current layout and Google's is **hierarchy**.
*   **Current:** Side-by-Side (Gauge on Left, Grid of 4 Cards on Right). This feels cramped because everything fights for attention.
*   **Google Style:** Top-to-Bottom (Active "Stage" on Top, Results "Tray" on Bottom).

### The New Layout Structure
We will split `#main-content` into two distinct visual zones:

1.  **The Active Stage (Top Section)**
    *   This is the "Hero" area. It takes up 60-70% of the vertical space during the test.
    *   **Contains:**
        *   The **Gauge** (Circular Progress).
        *   The **Real-Time Graph** (Canvas).
        *   The **Live Speed Number** (Huge typography).
    *   *Behavior:* When testing Download, this stage *becomes* the Download card. When testing Upload, it *becomes* the Upload card. The graph draws specifically for that phase.

2.  **The Results Tray (Bottom Section)**
    *   A clean row (flexbox) of 4 cards: Latency, Download, Upload, Jitter.
    *   *Behavior:* These act as "summaries".
        *   **Pending:** Dimmed / grayed out.
        *   **Active:** The card might highlight or "pulse" to show it's currently being measured in the Stage.
        *   **Complete:** Fills with the final number.

## 2. Detailed Implementation Steps

### A. HTML Restructuring (`index.html`)

Current structure:
```html
<div class="test-display">
    <div class="gauge-container">...</div>
    <div class="results-matrix">...</div>
</div>
```

**Proposed Structure:**
```html
<div class="speedtest-app-layout">
    <!-- 1. THE STAGE -->
    <section class="active-stage" id="activeStage">
        <div class="stage-content">
            <!-- The Gauge and The Graph Live Here Together -->
            <div class="gauge-overlay">
                <!-- Your existing gauge circle -->
            </div>
            <canvas id="realTimeGraph" class="stage-graph"></canvas>
            
            <!-- Large Status Text -->
            <div class="live-status">
                <span id="liveSpeedValue">0.0</span>
                <span id="liveSpeedUnit">Mbps</span>
            </div>
        </div>
    </section>

    <!-- 2. THE TRAY -->
    <section class="results-tray">
        <!-- The 4 Cards move here, horizontally aligned -->
        <div class="tray-card" data-metric="latency">...</div>
        <div class="tray-card" data-metric="download">...</div>
        <div class="tray-card" data-metric="upload">...</div>
        <div class="tray-card" data-metric="jitter">...</div>
    </section>
</div>
```

### B. CSS Styling Strategy (`layout.css`)

1.  **`active-stage`**:
    *   Height: `300px` to `400px`.
    *   Position: Relative.
    *   Background: Subtle gradient or clean white/dark surface.
    *   **The Graph:** Position the canvas *behind* the text but *inside* the stage. Make it full width and height of the stage. Use a fade-out gradient at the bottom so it blends in.

2.  **`results-tray`**:
    *   Display: `grid`.
    *   Columns: `repeat(4, 1fr)` (4 equal columns).
    *   Gap: `20px`.
    *   On Mobile: Stack to `repeat(2, 1fr)` (2x2 grid).

### C. JavaScript Logic Updates (`ui.js`)

1.  **Repurpose the Graph:**
    *   Instead of `varianceGraph` (which implies just jitter), rename it to `SpeedCurve`.
    *   **X-Axis:** Time (0 to 10s).
    *   **Y-Axis:** Speed (Mbps).
    *   **Draw Logic:** As the test runs, plot the speed points. Use `lineTo()` to create a smooth area chart. Fill the area under the curve with a gradient (Blue for Download, Purple for Upload).

2.  **Phase Transitions:**
    *   **Start Download:**
        *   Clear Graph.
        *   Set Graph Color -> Blue.
        *   "Stage" shows Download UI.
    *   **Start Upload:**
        *   **Freeze** the Download curve (or clear it).
        *   Set Graph Color -> Purple.
        *   "Stage" shows Upload UI.

---

## 3. Why This Solves "Cramped"

*   **Separation of Time:** You don't need to show the huge Download number *and* the huge Upload number at the same time. You only show the **Active** one in the big Stage. The completed ones move to the small Tray.
*   **Graph Purpose:** The graph becomes the "hero visual" of the test, visualizing the *stability* of the connection (smooth curve vs. jagged spikes) naturally, without needing a separate "Variance" box.

## 4. Visual References (Mental Model)

*   **Google Fiber:** Large central number, graph fills the bottom half of the central area.
*   **Ookla:** Large gauge, graph builds *under* the gauge line.
*   **Netflix Fast.com:** Only one huge number, simple graph appears at the end.

**Recommendation:** Aim for the **Google Fiber** model:
*   **Top:** "Checking Download..."
*   **Middle:** [ BIG GRAPH AREA + NUMBER ]
*   **Bottom:** 4 Columns for results.

This plan provides the roadmap to move your DOM elements and CSS to achieve that exact look.
