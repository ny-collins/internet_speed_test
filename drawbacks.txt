# SpeedCheck: Deep Codebase Drawbacks & Risk Analysis

**Date:** December 2, 2025
**Reviewer:** Gemini Agent

This document outlines potential drawbacks, edge cases, and risks identified in the codebase. These are not critical bugs (the app works well), but areas that could cause issues under specific conditions.

---

## 1. Network & Resilience Edge Cases

### ⚠️ Single Point of Failure: Hardcoded Backend URL
*   **Location:** `frontend/js/config.js` (inferred from previous reads) and `index.html` script block.
*   **Issue:** The backend URL defaults to `speed-test-backend.up.railway.app`. If Railway goes down, the entire application breaks.
*   **Risk:** High availability risk.
*   **Recommendation:** Implement a "failover" list of backend URLs. If the primary fails 3 times, automatically switch to a secondary endpoint.

### ⚠️ Worker "Zombie" State
*   **Location:** `frontend/js/worker-utils.js` (shared loop).
*   **Issue:** If the network connection drops *completely* (e.g., user unplugs cable), the `fetch` or `XHR` requests might hang until the browser's native timeout (which can be 60s+), freezing the "Cancel" button's responsiveness.
*   **Risk:** Bad UX during network outages.
*   **Recommendation:** Ensure strict timeout controllers (AbortController) are wrapped around every network call with a maximum timeout of 5-10s.

---

## 2. Performance Risks

### ⚠️ Layout Thrashing in Animation Loops
*   **Location:** `frontend/js/ui.js` -> `updateGauge`.
*   **Issue:** The `updateGauge` function reads DOM properties and writes styles inside `requestAnimationFrame`. If `calculateMaxScale` or other helpers trigger a reflow (style recalculation), this could cause "jank" on low-end Android devices.
*   **Risk:** Visual stuttering on cheap phones.
*   **Recommendation:** Batch all DOM reads before DOM writes. Ensure `calculateMaxScale` is pure math and touches no DOM.

### ⚠️ Memory Leak in Long-Running Sessions
*   **Location:** `frontend/js/ui.js` -> `STATE.varianceGraph.samples`.
*   **Issue:** While there is a `maxSamples` limit, the chart canvas context (`ctx`) is never explicitly cleared or garbage collected if the user navigates away (SPA-style) or if the graph is reset multiple times rapidly.
*   **Risk:** Minor memory creep if a user runs 50+ tests in a row without refreshing.
*   **Recommendation:** Ensure `samples` array is sliced strictly and the canvas context is managed efficiently.

---

## 3. Maintainability Concerns

### ⚠️ CSS Specificity Wars
*   **Location:** `frontend/css/layout.css`.
*   **Issue:** The media queries are mixed in with the main class definitions. As the app grows, finding the specific mobile override for `.results-matrix` will become difficult.
*   **Risk:** "Spaghetti CSS" in the future.
*   **Recommendation:** Adopt a stricter CSS methodology (BEM) or move all media queries to a separate `responsive.css` file or at the bottom of each component file.

### ⚠️ "Magic Numbers" in UI Logic
*   **Location:** `frontend/js/ui.js`.
*   **Issue:** Values like `270` (gauge degrees) and `300` (animation duration) are hardcoded.
*   **Risk:** If the design changes (e.g., to a 360-degree gauge), updating the JS logic will be error-prone.
*   **Recommendation:** Move these constants to `config.js` or `variables.css` (and read them via JS).

---

## 4. Accessibility (a11y) Gaps

### ⚠️ Dynamic Content Announcement
*   **Location:** `frontend/js/ui.js` -> `announceToScreenReader`.
*   **Issue:** Rapid updates (e.g., the variance graph numbers changing every 100ms) might flood the screen reader's speech buffer if not carefully managed, making the interface "chatter" too much.
*   **Risk:** Annoyance for screen reader users.
*   **Recommendation:** Ensure `aria-live` regions are set to "polite" and throttle announcements to important milestones only (Start, Phase Change, End), not every millisecond update.

### ⚠️ Color Reliance
*   **Location:** Quality Badges (Green/Yellow/Red dots).
*   **Issue:** If a user is Red-Green colorblind, the "Good" (Green) and "Poor" (Red) status dots might look identical.
*   **Risk:** Information conveyed by color alone.
*   **Recommendation:** Ensure the *text label* ("Good", "Poor") is always visible alongside the color dot, which seems to be the case, but verify contrast ratios for the text itself.

---

## 5. Summary of Priority Fixes

1.  **Failover Backend:** Critical for uptime.
2.  **AbortController Timeouts:** Critical for UX during failures.
3.  **Throttle Screen Reader Updates:** Critical for accessibility.
